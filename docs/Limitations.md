# Limitations

This page lists the syntax the packages do not inspect and the cases they leave unchanged.

- **C# only.** Only C# syntax is inspected: Razor, Visual Basic and F# source are not.
  A markup file on disk is [`stanza-markup`](https://github.com/Nickelony/Stanza/blob/main/src/Nickelony.Stanza.Markup/README.md)'s job.
  The analyzer reaches XML only in raw string literals and documentation comments.
- **Not formatters.** The blank line and brace rules add or remove blank lines only in the [gaps](https://github.com/Nickelony/Stanza/wiki/Terms) they own.
  The documentation layout rules lay out a comment's text, but only when [enabled](https://github.com/Nickelony/Stanza/wiki/Terms);
  [Which rule owns which gap](https://github.com/Nickelony/Stanza/wiki/Which-rule-owns-which-gap) maps each gap to its rule.
- **A fix that widens a line** can hand work to a width rule, which the next pass settles;
  see [Working with formatters](https://github.com/Nickelony/Stanza/wiki/Working-with-formatters#fixes-that-open-work).
- **The width is a target.**
  A line that holds a word or an element this package cannot break up stays longer than `stanza_max_line_length`,
  or `stanza_doc_max_line_length` for a documentation comment.
- **Generated code is skipped**, such as a file with an `<auto-generated>` header or a name ending in `.Designer.cs`;
  `generated_code = true` in the section that matches a file marks any other file as generated.
- **A gap lies only between two neighbors.** The first unit of a container gets no preceding blank line.
- **A `[SuppressMessage]` attribute is invisible to the rules that defer a gap.**
  A grouping rule that defers a gap to `ZA0004` still defers it when an attribute suppresses `ZA0004`,
  so that gap goes unreported. Disable `ZA0004` in `.editorconfig`, or silence it with a pragma, instead.
- **Preprocessor directives.** A gap touched by a directive is left unchanged,
  except around a region marker,
  which [ZA0046](https://github.com/Nickelony/Stanza/wiki/ZA0046-Separate-the-region-marker-from-its-neighbors) separates.
- **Tuple expressions are not inspected.** `(a, b)` holds deconstruction targets or return values,
  not the arguments and elements the delimited list rules claim.
- **The markup rules need a non-interpolated raw string literal that parses as one document**,
  and leave a subtree under `xml:space="preserve"` alone.
- **A documentation comment whose markup is broken is left alone** by the rules that check its markup,
  and so is one that holds a CDATA section, an XML comment or a processing instruction.
  The layout rules also leave a comment that holds a `<code>` block alone.
- **`ZA0206`, `ZA0207` and `ZA0208` still judge a comment with such markup or a `<code>` block**, since they read a tag alone.
- **Inside a `<list>` or `<table>`, only layout and item order apply.**
  [`ZA0204`](https://github.com/Nickelony/Stanza/wiki/ZA0204-Lay-out-the-items-of-a-documentation-list) lays out the items and [`ZA0213`](https://github.com/Nickelony/Stanza/wiki/ZA0213-Order-the-items-of-a-documentation-list) orders them.
  The clean-ups for blank lines, tags, periods and the `null` keyword do not read inside, as the page of each rule says.
- **A [reprint](https://github.com/Nickelony/Stanza/wiki/Terms) lays out a `<member>` body, not the whole file**,
  and declines some bodies; [Markup behavior](https://github.com/Nickelony/Stanza/wiki/Markup-behavior#bodies-a-reprint-leaves-as-written) lists which.
