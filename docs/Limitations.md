# Limitations

This page lists the syntax the packages do not inspect and the cases they leave unchanged.

- **C# only.** Only C# syntax is inspected: Razor, Visual Basic and F# source are not.
  A markup file on disk is [`stanza-markup`](https://github.com/Nickelony/Stanza/blob/main/src/Nickelony.Stanza.Markup/README.md)'s job.
  The analyzer reaches XML only in documentation comments and in the raw string literals that [`stanza_markup_literals`](https://github.com/Nickelony/Stanza/wiki/stanza_markup_literals) picks.
- **Not formatters.** The blank line and brace rules add or remove blank lines only in the [gaps](https://github.com/Nickelony/Stanza/wiki/Terms) they own.
  The documentation layout rules lay out a comment's text, but only when [enabled](https://github.com/Nickelony/Stanza/wiki/Terms);
  [Which rule owns which gap](https://github.com/Nickelony/Stanza/wiki/Which-rule-owns-which-gap) maps each gap to its rule.
- **A fix that widens a line** can hand work to a width rule, which the next pass settles;
  see [Working with formatters](https://github.com/Nickelony/Stanza/wiki/Working-with-formatters#fixes-that-open-work).
- **The width is a target.**
  A line that holds a word or an element this package cannot break up stays longer than `stanza_max_line_length`,
  or `stanza_doc_max_line_length` for a documentation comment.
  [`ZA1001`](https://github.com/Nickelony/Stanza/wiki/ZA1001-Shorten-a-long-line) reports such a line, unless a string or a URL holds its overflow.
- **Generated code is skipped**, such as a file with an `<auto-generated>` header or a name ending in `.Designer.cs`;
  `generated_code = true` in the section that matches a file marks any other file as generated.
- **A gap lies only between two neighbors.** The first unit of a container gets no preceding blank line.
- **A `[SuppressMessage]` attribute is invisible to the rules that defer a gap.**
  A grouping rule that defers a gap to `ZA0001` still defers it when an attribute suppresses `ZA0001`,
  so that gap goes unreported. Disable `ZA0001` in `.editorconfig`, or silence it with a pragma, instead.
- **Preprocessor directives.** A gap touched by a directive is left unchanged,
  except around a region marker and a conditional block, which
  [ZA0401](https://github.com/Nickelony/Stanza/wiki/ZA0401-Separate-the-region-marker-from-its-neighbors) and
  [ZA0402](https://github.com/Nickelony/Stanza/wiki/ZA0402-Separate-the-conditional-block-from-its-neighbors) separate,
  and except for a run of blank lines past the cap of [ZA0056](https://github.com/Nickelony/Stanza/wiki/ZA0056-Collapse-extra-blank-lines).
- **Positional patterns and designations are not inspected.** `(> 0, var y)` and `var (a, b)` are neither a tuple literal nor a tuple type,
  so the delimited list rules leave their gaps alone.
- **The markup rules need a non-interpolated multi-line raw string literal that parses as one document**,
  and by default one that a comment or an attribute marks as XML, as [`stanza_markup_literals`](https://github.com/Nickelony/Stanza/wiki/stanza_markup_literals) says.
  They leave a subtree under `xml:space="preserve"` alone.
- **A documentation comment whose markup is broken is left alone** by the rules that check its markup,
  and so is one that holds a CDATA section, an XML comment or a processing instruction.
- **A top-level element that holds a `<code>` block, an `<include>` or an `<inheritdoc>` stays as written.**
  The layout rules, [`ZA0910`](https://github.com/Nickelony/Stanza/wiki/ZA0910-Capitalize-the-documentation-text),
  [`ZA0911`](https://github.com/Nickelony/Stanza/wiki/ZA0911-End-the-documentation-text-with-a-period)
  and [`ZA0912`](https://github.com/Nickelony/Stanza/wiki/ZA0912-Mark-the-language-keywords) skip that element and handle the elements beside it.
- **`ZA0906`, `ZA0907` and `ZA0908` still judge a comment with such markup or a `<code>` block**, since they read a tag alone.
- **Inside a `<list>` or `<table>`, only layout and item order apply.**
  [`ZA0904`](https://github.com/Nickelony/Stanza/wiki/ZA0904-Lay-out-the-items-of-a-documentation-list) lays out the items and [`ZA0914`](https://github.com/Nickelony/Stanza/wiki/ZA0914-Order-the-items-of-a-documentation-list) orders them.
  The clean-ups for blank lines, tags, capitals, periods and the `null` keyword do not read inside, as the page of each rule says.
- **A [reprint](https://github.com/Nickelony/Stanza/wiki/Terms) lays out a `<member>` body, not the whole file**,
  and declines some bodies; [Markup behavior](https://github.com/Nickelony/Stanza/wiki/Markup-behavior#bodies-a-reprint-leaves-as-written) lists which.
